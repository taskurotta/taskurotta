# Домен: metrics

## Обзор контекста (Bounded Context)
Собирает и хранит в памяти оперативные метрики оркестратора задач — операции актёров и процессов (старт, poll, release, решение, добавление в очередь) и выборочные значения (размеры очередей, память, исполнители) — и предоставляет ряды данных веб-консоли.

Что домен НЕ делает:
- не персистирует метрики: хранилище — память процесса, данные утрачиваются при перезапуске;
- не выполняет пороговых проверок и оповещений;
- не хранит состояние карт Hazelcast (состояние внутренних карт — забота инфраструктурного слоя).

## Dependencies | Зависимости
Нет (кросс-доменные зависимости не задокументированы: это первый домен базы знаний).

## Ubiquitous Language | Единый язык
- **Метрика (Metric)**: счётчик именованной операции; идентифицируется именем (перечисление `MetricName`), один экземпляр на имя (синглтон).
- **Датасет (data set)**: срез метрики по конкретному субъекту (актёр или джоб в форме FQN+версия). Пара «метрика + датасет» — ключ хранимого ряда.
- **Отметка (mark)**: единичное событие; увеличивает счётчик ключа. Ключ-счётчик (контрольная точка) появляется при первой отметке и после этого не удаляется; хранимая строка ключа может удаляться (см. инварианты) и воссоздаётся следующей отметкой.
- **Дамп (tick)**: фоновый снимок: планировочная задача, раз в период дампинга, обходит ВСЕ существующие ключи метрики и передаёт их состояние обработчику — в том числе ключи без активности с прошлого дампинга (count = 0, mean = NaN). Дамп пишет бин только при count > 0: для неактивного ключа строка и точка не создаются, счётчик сбрасывается.
- **Общий (агрегатный) датасет**: строка, где датасет = имя метрики. Создаётся двойной отметкой; в консоли помечается флагом «general» и используется для агрегированных графиков.
- **Кольцо (ring)**: замкнутый массив фиксированной длины, адресованный по времени данных: по переполнению перезаписывается самый старый бин.
- **Бин (bin)**: временной интервал фиксированной длины (бин) внутри кольца; точка — агрегированное значение всех отметок, попавших в бин (count + взвешенное среднее для методических метрик, последнее значение для числовых). Накопление — только внутри одного абсолютного интервала бина; при переиспользовании слота (полный оборот кольца) данные прежнего оборота сбрасываются, кольцо остаётся скользящим окном.
- **Хранилище (holder)**: синглетон-контейнер строк — хранилище «последний час» (разрешение по умолчанию 10 с), хранилище «последний день» (разрешение по умолчанию 2 мин) и числовое хранилище для периодических метрик (разрешение по умолчанию 1 мин); разрешения настраиваются, число строк в хранилище ограничено (по умолчанию 1500).
- **Строка (row)**: ряд данных одного ключа; строка методического хранилища имеет два кольца (count и среднее), строка числового хранилища — одно.
- **Точка (point)**: агрегированное значение бина (число + время бина); в отдаче консоли — только полные бины.
- **Вытеснение (eviction)**: при превышении лимита строк хранилища удаляются строки с самым старым временем последней активности среди невидимых (неактивны дольше разрешения окна); видимые строки не затрагиваются; невидимых нет — вытеснение пропущено со счётчиком.
- **TTL (время неактивности)**: периодическое удаление строк, неактивных дольше TTL (по умолчанию 24 ч); ключ-счётчик при этом не удаляется, следующая отметка воссоздаёт строку.
- **Периодическая метрика**: выбираемое значение, а не счётчик (размер очереди, потребление памяти); пишется в числовое хранилище.
- **Консоль**: веб-интерфейс, читающий ряды через REST API.

## Публичные контракты (API)

### Public API (для внешних клиентов)
Веб-консоль (модуль dropwizard, `ru.taskurotta.dropwizard.resources.console.metrics.MetricsResource`):
- `GET /console/metrics/data` — параметры: `metric` (имя метрики), `type` (dataType: rate/mean/size), `period`, `scope`, `dataset` (список через запятую; пустой — пустой ответ), `zeroes` (default true), `smooth` (default −1); отдача — датасеты метрики за запрошенное окно, точки `[time, value]`, `[null, null]` — маркер прогона пропущенных значений;
- `GET /console/metrics/options` — доступные метрики, датасеты (с флагом «general» у агрегатных), типы данных, скоупы и периоды;

Отдельная проекция в `docs/public/` не создавалась.

### Internal API (для других модулей системы)
- `Metric.mark(datasetName, value)` — регистрация события из сервисного модуля;
- `MetricsFactory.getInstance(...)` / `MetricsFactory.getPeriodicInstance(...)` — получение синглтона метрики; поток дампинга расписывается при первом использовании.

## Domain Invariants | Инварианты и правила бизнеса
1. Ключ-счётчик (контрольная точка) создаётся при первой отметке и никогда не удаляется: набор ключей монотонно растёт за время жизни процесса. Хранимая строка ряда создаётся при первом использовании и может удаляться (TTL, вытеснение при превышении лимита); следующая отметка воссоздаёт строку с полным счётчиком.
2. Кольца фиксированной длины, замкнутые и адресованные по времени данных: бин определяется абсолютным временем данных (не временем жизни процесса); размер кольца выводится из свойства длины бина: час — 3600/бин секунд (по умолчанию 360 бин × 10 с), день — 86400/бин секунд (по умолчанию 720 бин × 2 мин), периодические — 86400/бин секунд (по умолчанию 1440 бин × 1 мин).
3. Дамп пишет бин только при count > 0: для неактивного ключа строка и точка не создаются, бин сохраняет предыдущее значение; счётчик ключа сбрасывается для каждого существующего ключа.
4. При превышении лимита строк хранилища вытесняются только невидимые строки (последняя активность старше разрешения окна — 1 ч для часового, 24 ч для суточного и числового хранилищ); видимые строки не затрагиваются; невидимых кандидатов нет — вытеснение пропущено со счётчиком. Строки, неактивные дольше TTL, удаляются; статус-строка (INFO) фиксирует число строк, вытесненные/удалённые/пропущенные и heap JVM по периоду.
5. Все данные метрик существуют только в памяти процесса; после перезапуска хранилища строятся заново с нуля.
6. Видимый ряд данных покрывает не более последних 24 часов (крупнейшее кольцо — 24 часа).
7. Двойная отметка: операция актёра отмечается дважды — по датасету актёра (FQN+версия) и в агрегате (датасет = имя метрики); часть отметок условна (успешный poll — только если poll вернул задачу, ошибка решения — только при ошибке в решении).
